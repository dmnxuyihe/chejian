# 计划管理新增功能测试流程

## 一、测试准备

1. 启动项目并打开 `http://127.0.0.1:5193/`。
2. 首次加载后，系统会在计划相关 JSON 集合为空时写入一批演示数据；不修改现有数据库表结构。
3. CSV 文件位于 `docs`，同内容 XLSX 文件位于 `outputs/planning-import-samples`。
4. 若页面仍显示旧数据，先刷新页面。不要直接清空 PostgreSQL 表。

## 二、年度计划与交验统计

入口：`#/functions/plans/annual-plan`

1. 检查标题栏样式与月度计划页面一致。
2. 查看年度计划列表、季度数量和机车详情。
3. 切换到“年度交验统计”，选择年度和委修段。
4. 预期：只选委修段时，曲线和明细均只统计该段；鼠标悬浮某个月份时，浮层显示该月全部委修段的数据。
5. 进入“计划完善与统计”的年度页签，检查年初计划、调整后计划、实际进车和预计交车月模拟数据。

## 三、月度计划与计划导入

入口：`#/functions/plans/monthly-calendar`

1. 在“月度计划”和“计划导入”之间切换，检查切换按钮、标题栏和页面主样式一致。
2. 使用 `年度月度计划导入混合示例.csv` 进行预览。
3. 检查系统是否区分年度与月度记录、标出错误行，并只允许导入校验通过的记录。
4. 回到月度计划，检查日历中的机型机号、修程、修次及详情弹窗。
5. 新增一条计划后执行修改和删除。删除时必须出现二次确认提示。

## 四、配件月计划

入口：计划与排程 → 配件计划 → 计划完善与统计 → 配件月计划

1. 导入 `配件月计划模拟导入.xlsx` 或同名 CSV。
2. 预期预览 4 行均可导入，月份为 2026-12，方向可正确转换为 `DOWN/UP`。
3. 导入后检查下车计划数量、测算数量、上车计划、公里匹配值。
4. 新增一条草稿并删除，确认弹出删除警告。
5. 对上车草稿执行“确认并提报”，再到审批中心检查流程记录。

## 五、整车临修计划

入口：`#/functions/plans/temporary-repair`

1. 页面应预置 2 条演示记录：1 条待审核、1 条草稿。
2. 使用委修段、状态和关键词单独筛选，检查列表和统计结果。
3. 导入 `整车临修计划模拟导入.xlsx` 或同名 CSV，预览应显示 3 条可导入记录。
4. 导入后修改一条草稿，上传 PDF、DOC、DOCX、PNG、JPG 或 WEBP 格式的方案附件。
5. 提报后记录不可直接修改或删除；草稿删除时必须出现二次确认。

## 六、配件临修计划

入口：技术管理 → 配件临修计划

1. 页面应预置 2 条演示记录：车轴待审核、制动盘草稿。
2. 导入 `配件临修计划模拟导入.xlsx` 或同名 CSV，预览应显示 3 条可导入记录。
3. 修改草稿并上传方案，提报后检查状态改为待审核。
4. 未上传方案时，提报按钮应不可用。
5. 草稿可删除且必须确认，已提报计划不能删除。

## 七、审批中心

入口：审批管理 → 计划审核与审批

1. 初始应看到整车临修和配件临修两条待审核模拟记录。
2. 配件临修点击“审核并发布”，预期直接进入已发布。
3. 整车临修点击“审核通过”，再点击“审批发布”，预期先进入待审批、再进入已发布。
4. 返回对应计划页面，检查业务记录状态同步更新。

## 八、验收通过标准

- 标题栏和页签风格统一，页面无明显错位。
- 增、新建、修改、查询、删除和删除提示按状态约束生效。
- CSV/XLSX 均可预览，错误行不写入，正确行可批量导入。
- 模拟数据首次进入即可展示，刷新后仍保留。
- 审批状态和业务计划状态保持同步。
- 不新增或修改 PostgreSQL 业务表字段，新增演示内容保存在现有 JSON 应用状态中。
