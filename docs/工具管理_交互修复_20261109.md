补充改进：

- 业务记录提供待办理、已办结、全部范围，导出遵循当前记录类型和过滤条件。
- 连续扫码选择支持成功、重复和未知码提示；扫描用于选中工具，数量在办理表单确认。
- 自定义批量数量和套装勾选也参与误关保护。
- 检定/维修结果须明确选择；证书编号不代替合格判定。不合格进入报废审核，合格才返库。
- 工具状态同时说明检定到期/缺少检定及暂停使用的限制；账面数和可领用数有明确解释。
- 经办姓名仍允许按业务需要手工记录；匹配现有人员时审计附带人员ID，这不等于新增登录认证或角色权限。

## 执行验证

```text
npm test
npm run test:tools
npm run test:tools:ux
```

整套测试包括计划、排程、持久化、导航、工具业务、PostgreSQL事务、台账CRUD及136个页面冒烟检查。工具领域组合测试为1000组、6100条断言。新增专项脚本 `tests/tool_ux_regressions.mjs` 对25项场景/观察断言，包括断网重试、并发冲突和“盘点→申请→独立审核→扣账”的数据库及浏览器链条。

证据输出在 `test-artifacts/tool-ux-fixes/`。这些是合成夹具与独立临时schema，脚本 finally 清理测试数据；未往正式工具库插入测试工具或盘点单。

本轮验证的软件边界不包含真实RFID读写器、智能柜及门禁实机验收，也不把专家走查或自动化测试称为真实用户访谈/完整无障碍认证。

## 交付与数据兼容

本地服务需重启以加载更新的领域命令。业务表结构无新增；盘点进度版本、差异及申请关联号经现有扩展数据字段持久化，原有记录可读。启动前正式库 revision 为45，没有历史盘点单，因此没有需要反推恢复的旧盘亏库存。新逻辑不回写历史事实。
