# PC1演示操作与验收

本次范围：检修计划排程五项，以及整车检修管控中的任务状态、已完成记录、图片和视频查看。按[需求表逐项对应](演示计划_需求表逐项对应.md)定位功能；不包含PC2/PC3/PC4的UE、AGV及天车动作。

## 启动和入口

配置项目根目录 `.env` 的 `DATABASE_URL`，执行 `npm ci`、`npm run db:init`、`node start.js --port=5193 --no-open`。已有数据库和配置保留，初始化可重复执行。

- 月度计划导入：`/#/planning/plans`。
- 月度计划查询：`/#/planning/g2-p2`。
- 两车模拟、拖动及确认：`/#/scheduling/dashboard`。
- 正式班组清单及甘特：`/#/scheduling/gantt`。
- 单车日历、甘特、资源及整车管控：`/#/scheduling/workforce`。
- 车间每日任务日历：`/#/scheduling/workshop-calendar`。
- 车间管理人员的“机车检修进度监控”也接入单车管控。

界面按操作流程重新组织，默认使用深灰蓝与青绿高亮业务工作区。顶部只有“月度计划、智能排程、单车检修、车间日历”一套主导航；右上角菜单可展开完整角色功能，亦可切换明暗主题。计划列表和月度日历分别显示；上传进入预览时，只显示待核对内容。Excel模板和填写指引在计划列表右侧，CSV模板在其下方展开。排程页左侧选车或查看模拟甘特图，右侧统一设置截止时间、核对资源和确认发布；演示计划入口位于选车日历底部的“演示数据”。生成模拟后可展开“修改本次选车”返回日历；甘特图按车辆分组，每行“⋯”菜单提供精确调整及锁定/解锁。班组清单按行展开，正式甘特图也按需展开。资源明细在页面下方查看。

## 推荐演示顺序

1. 在月度计划页导入相邻日期入段的两辆车，查看入段日历及车辆详情。也可在日计划编排页点击“导入两车演示计划”，新增或选取 `HXD1C-DEMO01/02`，入段日期为2026年10月27、28日；不会清空已有车辆或直接生成正式排程。
2. 在编排页的月度日历中勾选两辆车，填写最晚完成时间。点击“核对人员、工具、物料”。人员及工具按需求和具体占用时段检查，物料按所选任务累计检查；有缺口时生成模拟会被阻止，可在下方单车资源明细核对库存数量。
3. 点击“生成模拟排程”，两辆车分别生成构架4项、轮驱16项，共40项任务。保留轮对压装至反压的48小时工艺等待；人员、工位、设备、工具、配件实例不能在不允许的时段重复占用。显式配置的非工作日会避开，未配置日期按连续作业处理。
4. 拖动甘特条调整任务，按15分钟吸附；也可点击该行“⋯”中的“调整时间”精确设置开始时间。作业时长保持工艺值，调整后该时间自动临时锁定。锁定任务需在“⋯”中先解锁再移动，方向键和回车也可操作。
5. 点击“重新模拟排程”，保留锁定任务的指定时间，为其余任务重新分配时段及资源。前后置、锁定或截止时间冲突会明确列出，不能确认。可解除冲突锁定或更改截止日期后重新模拟。
6. 校验通过后点击“确认并发布当前方案”，再次确认。正式任务、资源分配、发布版本和班组清单在同一次PostgreSQL保存中写入。此前的正式排程在模拟、调整或取消时保持不变；取消不改变原入出段标记。历史发布版本归档，查询和执行使用当前版本。
7. 在“日计划发布与任务下发”查看各车各班组的任务、人员、工具、物料及配件清单。共享工序的需求以任务为单位，清单用于班组备料，不因多个班组查看而重复扣减库存。
8. 进入“整车日计划/修程查询”，选择车辆，在“每日任务日历”“甘特图进度”“人员/工具/物料”“整车检修管控”间切换。月度车辆详情也提供跳转到同一车辆完整信息的入口。再进入车间任务日历，按日查看两车汇总及各车任务。
9. 在“整车检修管控”查看所有正式任务状态；已完成任务可打开“查看记录”。已有提交显示提交人、时间、说明、测量项、数值、单位、图片和视频。没有提交时明确显示暂无数据，不生成虚假的检测结果。

演示PC1整车管控时只需查看。准备资料时，可由已有作业页面将任务正常开始、完成，然后在该任务记录中点击“补充检修记录”，上传真实资料。支持PNG、JPEG、WebP及MP4、WebM，每份记录最多12个附件、总计8MB。视频是否能播放仍取决于浏览器对其实际编码的支持，已实测WebM播放。

## 本轮补齐的操作

- 计划列表点击“查看详情”，未提交且没有排程/历史版本、审批/下发、接车记录或模拟占用的计划可点击“修改计划”或“删除计划”。删除需要再次确认。已进入检修流程的计划显示保护原因。
- 单车检修页的“车辆与检修信息”显示机型、机号、配属局/段、修程/修次、计划与实际入段、上台日期和天数。“记录入段 / 上台”录入实际时间，拒绝未来时间、上台早于入段及晚于已发生作业的记录；更正已有时间必须填写原因。
- 实际入段使用原业务表`vehicle_repair.actual_entry_at`；上台时间`onStandAt`与时间更正历史`lifecycleHistory`由现有PostgreSQL应用状态的车辆扩展字段保存，随备份恢复，不需要新数据库配置。缺失时间显示“未填写”。
- 按日和按车查询共用车辆详情。查询日第几天以实际入段为基准，未接车时明确标为计划天数；总天数按当前展示方案的计划入段至末项任务结束计算，午夜结束不额外占用次日。
- “整车检修管控”选择工位查看进度条、任务、人员、计划/实际时间、累计实际作业时长、超时未完成预警、设备异常及质检未通过。仅使用已发布正式任务，不把模拟排程作为现场执行。工位停留从该车在该工位首次实际开工至全部任务完工，未完工则截至统计时间；未开始不推算实际时长。“刷新进度”更新统计时间。
- 独立标签页作业人员开始/完成任务后，已打开的监控页通过现有约3秒数据库轮询更新。已完成行的“查看记录”进入检测数据、图片和视频；未提交时明确提示。没有扩展完整提票、返工派活或竣工交验单业务。
- 作业开始、完成和质量确认只允许操作当前正式发布版本；未发布的个人任务显示“待正式发布”。首次开工将车辆状态更新为“检修中”，不会自动补造实际入段时间。月度日历、列表及打开的详情跟随数据库版本重新查询，跨标签页可看到最新状态。
- 修改未提交计划时保留原入段时分秒；仅调整日期时也保留原时刻，并据此重新校验要求交车时间。

## 数据与保存

- 生成和调整的模拟方案保存在共享数据库的应用状态中，尚未替换正式任务；刷新可继续。确认前会重新检查计划和资源是否变化，有变化须重新模拟。
- 确认通过现有版本冲突保护保存；失败不会把待确认方案误报为已正式发布。
- 原30张业务表继续使用。新增辅助表 `pc1_maintenance_media` 存储图片、视频二进制，检修记录元数据及班组下发快照保存在应用状态中；无需新增数据库连接配置。
- JSON演示备份含附件信息和地址，不包含附件二进制。迁移含视频/图片的资料请备份整个PostgreSQL数据区，包括辅助媒体表。
- 记录接口供本系统补充资料及后续工位端对接：`POST /api/pc1/records`；查询 `GET /api/pc1/records?vehicleRepairId=...`；附件支持字节范围读取。记录只能关联已完成的正式任务，提交具有请求编号去重及事务保护。

- `npm run test:pc1:operations`：实际时间顺序、更正原因、保护计划、查询天数、工位实际时长、超时、正式/模拟隔离、PostgreSQL保存恢复及过期版本写入拒绝。
- `tests/pc1_operations_ui.py`：独立PostgreSQL数据区验证实际时间表单、跨标签页开始/完成反馈、监控刷新恢复、计划修改删除入库和375宽布局。

- `npm test`：原业务链、角色路由、计划/备份及129页面浏览器冒烟回归。
- `npm run test:pc1`：两车模拟隔离、短缺阻断、锁定重算、截止日期、过期方案、取消、确认版本、班组清单、真实数据库保存恢复、记录附件事务和字节范围读取。

- `tests/pc1_workflow_ui.py`：真实Edge浏览器鼠标拖动、锁定重算、取消、确认入库、各类查询、真实图片及可播放WebM提交/查看/刷新恢复，以及手机布局。测试启动独立临时PostgreSQL数据区，结束后清理，不写演示用 `pc1`。
- `tests/workspace_ui.py`：新版五个主页面、小型SVG图标与流程提示、无大幅插画、单一主导航、完整角色导航、每页一个主要操作、模板菜单键盘操作、跳到工作区、明暗主题保存、手机导航、375/390/768/1024/1440宽度、记录弹窗焦点恢复及现有业务数据不变检查。界面截图保存在 `test-artifacts/workspace-simple/`；图形及视觉规范见[界面设计说明](PC1_界面设计说明.md)。
- `tests/workspace_consistency.py`：18个角色的145个路由，覆盖桌面深色、手机深色和桌面浅色，共435次页面一致性检查；同时检查角色选择、功能导航、弹窗焦点和业务数据不变。截图与报告保存在 `test-artifacts/workspace-unified/`。

界面测试使用Python Playwright；本机依赖安装在忽略目录 `test-artifacts/python-deps`。运行脚本时优先使用已配置的Python运行环境，Windows默认浏览器为Edge，亦可设置 `PC1_BROWSER_CHANNEL`。

测试截图及本次界面报告位于 `test-artifacts/pc1-complete/`。通过上述验收不表示需求表中的审批、全量仓储、外部系统同步或其他电脑的实体设备联动已经完成。
