# 工具管理：使用、设备接入与验收

更新日期：2026-11-06。

## 入口与交付范围

完整主站侧栏“资源台账 → 工具管理”，地址为 `http://127.0.0.1:5193/#/functions/assets/tool-register`。原工具管理相关链接也进入该模块，对应显示五个视图之一。

工具台账、借还与调拨、检定与维修、盘点与预警、智能设施共用一份工具数据。真实设备需要厂家网关把设备事件转换为下述JSON接口。本项目提供接收接口、认证、去重、业务处理和联调模拟；没有连接实际RFID读写器、工具柜控制器或门禁硬件，不能把软件模拟当作现场验收。门禁事件只记录已经发生的通行，不提供远程开锁。

第19行的任务工具清单继续沿用任务发布功能。第195行的工序工具需求继续沿用现有绑定，工具规格在字典中维护。第199行的工具防错提供手动任务核验，以及设施领用事件携带作业任务号时的比对与异常记录；设备自动登销记和整车间工装协议不在工具柜网关中假装实现。

在工具字典行点击“工序绑定”可新增或修改该工具在工序中的需求数量。检修作业页对已纳入实物台账的工序工具显示“核验工具”，可扫描或输入标签并填写数量；不足、失效、停用或不匹配会阻止开始作业。有效核验保留24小时，实际开始作业时再次检查当前状态和可用数量。设备领用带作业任务号时也会生成对应核验记录。尚未接管为实物的旧品种仍沿用原有流程，不凭空要求不存在的实物标签。

## 第一次使用

1. 打开“工具台账”。没有实物时，点击提示中的“建立工具库”，填写编码、名称和经办人。需要跨库调拨时再建立第二个工具库。
2. 展开“工具字典与库存接管”。现有品种点击“接管库存”，选择工具库，填写唯一批次编号。系统把旧数量转成按数量管理的实物，不额外增加库存。相同品种只能接管一次。
3. 新品种先点“新增工具品种”，维护名称、编码、规格、分类、厂家和低储阈值；再点页首“新增实物”。单件必须数量为1，按数量管理可登记批次数量。
4. 单件可填写条形码/RFID标签。设置定检周期时同时登记最近合格检定日期。缺少日期或已经到期的工具不能领用，需先送检。字典阈值可按全库汇总或指定工具库设置，均可产生低储提醒。
5. 如需工具包，展开“工具套装”，选择同一工具库内的成员并填写数量。借出期间不能修改套装组成。

## 业务操作顺序

### 借用与归还

“借还与调拨 → 办理领用”选择实物或在台账套装行选择“领用整套”，填写数量、领用人、类型、预计归还时间和经办人。填写关联作业任务后会校验工具是否属于该工序需求。库存不足、定检失效、品种停用时拒绝领用。

在借还记录点击“办理归还”，选择工具、数量、归还人和经办人。支持分次或代还，不允许多还。列表按未还量显示，所有成员归还或经审核退出后单据完成。查询可使用工具编号、名称、领用人和借用类型，并可筛选工具库与状态。归还人的真实身份需部署登录系统或现场身份设备后进一步核实。

### 跨库调拨

点击“新建调拨”或台账“更多 → 调拨”，选择调入库和数量。创建后预留库存；调入人通过“接收 / 取消”确认。接收后入新库，取消则释放预留。套装成员先调整套装组成再调拨。

### 送检、送修和报废

“检定与维修 → 送检 / 送修”登记实物、数量、单位和说明。办理中的数量不可领用。完成时登记结果与证书编号/结论：合格回库；不合格自动生成待审核报废申请。

台账“更多 → 遗失 / 报废申请”可主动申请。借出期间遗失或损坏时填写关联借用单号。审核在“检定与维修 → 遗失与报废审核”办理，填写不同于申请人的审核经办人和意见。批准扣减账面数量并保留记录；驳回普通遗失报废释放占用，驳回维修不合格转报废的申请时仍停用该批工具，避免未经处置继续领用。

### 盘点和预警

“盘点与预警 → 新建盘点”，选择工具库。填写全部实盘在库数量与差异说明后确认。确认按差异调整库存，历史可查；旧盘点单遇到库存变化须取消后重建。预警可进入工具详情、归还、阈值维护或异常处置。

### 智能设施联调

“智能设施 → 添加设施”，维护编码、工具库和工具柜/无人室类型。每台设施可点“模拟事件”，填写事件类型、工具标签、人员及相应单据字段。模拟领还会实际更新业务库存，请用专门的测试工具。模拟不会把设备标记为在线。

标签盘点事件只比对标签，生成缺少或多出的异常；不会擅自扣减库存。核对后仍通过实物盘点确认差异。仅真实设备通信更新最近通信时间；两分钟未通信显示未连接/离线。

## 数据保存与兼容

原工具主数据继续保存到PostgreSQL的 `tool` 表，工序绑定继续使用 `task_tool_requirement`。工具实物、借还、调拨、服务、盘点、设施、事件和工具操作审计保存在同一数据区 `application_state.payload.appState.toolManagement` 的JSONB中；遗失/报废申请的审批记录写入现有的物理表 `approval_record`，与业务状态在同一事务内提交。`approval_record` 使用 `business_type='TOOL_DISPOSAL'` 标识工具处置审批，`business_id` 关联遗失/报废单，申请创建时写入 `PENDING`，审核时更新 `APPROVED` 或 `REJECTED`、审核人、意见和处理时间。没有新建第二个工具数据库，也没有仅保存在浏览器。

旧数据缺少工具管理对象时以空台账兼容加载，不自动编造工具库或单件编号。旧工具按原数量继续供排程使用，手工接管后使用实物计算。接管后的数量不能通过通用资源页面直接修改或删除，须通过业务或盘点处理。

每次操作记录经办人、时间和审计；带请求编号去重，两个窗口同时办理时有数据版本冲突保护。检定、停用和实物库存变化参与排程资源核对，既有模拟方案必要时须重新计算。对外演示环境仍沿用项目现有访问机制，未在本次增加完整账号认证和权限系统。

## 设备协议

在本机 `.env` 或服务环境变量设置 `TOOL_DEVICE_TOKEN`，至少24个随机字符，不提交Git、不填入前端页面。未配置时接口返回503，错误密钥返回401。重启服务后生效。

接口：`POST /api/tools/device-events`。请求头 `Content-Type: application/json`、`X-Tool-Device-Token: <服务器配置的密钥>`。

```json
{
  "requestId": "cabinet-01-checkout-000001",
  "actor": "工具柜网关",
  "payload": {
    "deviceId": 1,
    "eventId": "checkout-000001",
    "eventType": "CHECKOUT",
    "tag": "现场标签值",
    "employeeId": 1,
    "quantity": 1,
    "dueAt": "2099-01-01T18:00:00",
    "scheduleTaskId": 1
  }
}
```

示例编号均须替换为当前库中的实际编号，日期为协议格式示例。真实请求时间由服务器记录，不能用请求中的日期伪造设备在线状态。

| eventType | 必填业务字段 | 处理 |
| --- | --- | --- |
| HEARTBEAT | deviceId、eventId | 更新真实设备最近通信时间。 |
| ENTRY | deviceId、eventId、employeeId | 记录门禁通行。 |
| CHECKOUT | deviceId、eventId、tag、employeeId、dueAt；quantity默认1 | 标签领用。可附scheduleTaskId进行工序比对。 |
| RETURN | deviceId、eventId、tag、employeeId、loanId；quantity默认1 | 标签归还到对应借用单。 |
| INVENTORY | deviceId、eventId、tags字符串数组 | 对比本库在库标签，记录差异，人工盘点确认后调账。 |

deviceId在所有事件中必填，设施须启用。每次业务请求的requestId须唯一；通信重试保留相同requestId和内容。同一设施的eventId也不能代表不同内容。认证成功但标签错误、工具不匹配或库存不足时，接口返回已接收并将 `eventStatus` 设为 `ERROR`，不扣减库存；网关必须检查该字段，不能仅凭HTTP200判断领用成功。

普通页面使用 `POST /api/tools/commands`，包含type、payload、actor、requestId和当前revision。只用于项目当前的受控演示访问环境。`GET /api/tools/alerts` 返回实时预警。所有写入和工具主表更新共用数据库事务。
