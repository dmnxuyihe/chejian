# 工具管理：使用、设备接入与验收

更新日期：2026-11-07。

内容以当天上午 `613605e` 版本为基准，保留原业务及追溯能力；具体对照见[上午版内容对照](工具管理_上午版内容对照_20261106.md)。

## 入口与交付范围

完整主站侧栏“资源台账 → 工具管理”，地址为 `http://127.0.0.1:5193/#/functions/assets/tool-register`。原工具管理相关链接也进入该模块。基础资源中的“工具管理”以及单车资源清单中的工具维护均进入这个统一入口，不再提供另一套工具增删改或直接改库存表。主页面为统一工具大表。最上方显示全局状态统计，其下为查询条件；有编号、无编号、套装和待完善登记作为表头筛选值，不单独铺设功能页签。

本轮按需求表156—166行的11项工具管理需求组织业务。主台账包括已有实物、套装和待完善的原库存。真实设备需要厂家网关把设备事件转换为下述JSON接口。本项目提供接收接口、认证、去重、业务处理和联调模拟；没有连接实际RFID读写器、工具柜控制器或门禁硬件，不能把软件模拟当作现场验收。门禁事件只记录已经发生的通行，不提供远程开锁。

## 页面布局与查询

1. 最顶部是全部工具状态统计，包括原库存的工具总量、在库、借出、送检送修、待审核、待登记及预警。筛选列表不会改变全局统计；套装组成不重复累计工具件数。
2. 上方查询条件可按名称、编号、条形码、工具库、当前状态、未归还的借用类型及送检送修单位查找。送检查询覆盖进行中与已完成记录。
3. 列表中工具名称和编号分列，条形码/RFID只显示原始值；入库时间、最后检修时间、最近检定时间、检定有效期及当前状态分别显示。旧数据没有登记过的时间显示“未登记”，不编造日期。
4. 点击表头“▾”可搜索并勾选多个筛选值，组合多个列的条件。台账类型筛选包含有编号工具、无编号工具、套装和待完善登记。
5. 左侧勾选可多选；表头勾选只全选当前查询结果。底部清单始终显示全部已选工具、编号与当前状态，切换查询不会悄悄取消选择。可从底部逐项取消或清空。勾选后保留表格滚动位置。
6. 不勾选工具时，底部“导出筛选结果”只导出当前查询及表头筛选后的行；已有勾选时，按钮变为“导出所选工具”，包含跨查询保留的全部已选项。

## 底部操作

所有业务和基础维护按钮都在表格下方。借出、归还、调拨、送检、送修、遗失、报废、登记检修结果、接收调拨和审核支持批量选择，并在确认前列明每项数量及来源。带 * 的字段必填，仅可选字段标注“（可选）”；逐行数量、编号会在提交前校验。批量任意一项不合法时整个提交不保存。

主台账底部只保留6个固定入口，不再铺满所有功能：

- 新增工具、仓库盘点、盘点记录、业务记录与预警、工具资料、导出筛选结果（有勾选时导出所选工具）。
- 勾选工具后，额外显示“办理所选工具”，按当前状态出现借出、归还、调拨、送检、送修、遗失申请、报废申请及相应后续处理；这些业务不使用“更多”菜单。只有待接收、检修中、待审核记录才显示接收、登记结果及审核按钮。
- 工具资料内用明确标签切换工具字典、工具分类、工具套装、智能设施，各表保留增删改。新增套装也在这里。
- 业务记录与预警统一查询借还、调拨、送检、送修、遗失报废审核、综合预警、设施事件及审计，业务记录导出也放在其中。

上午版已有内容继续保留。标签与状态、工序绑定和作业工具核验移到单件“详情与记录”底部，工具字典仍可绑定工序。业务记录支持按类型、状态及人员、工具、单位关键词查询，选中单据后在表下方办理；设施表显示在线/离线和最近通信时间，异常事件可登记处置。

| 操作 | 填写及后续步骤 |
| --- | --- |
| 新增工具 | 选择品种及所属工具库，填入库数量、入库时间。无需选择“管理方式”；有独立编号时填写编号，不填写时按数量登记并生成批次登记号。条形码、检修时间、检定时间等可选字段直接展示，不折叠隐藏。 |
| 完善登记 | 在表头筛选“待完善登记”，勾选原库存后在底部完善。登记只转入台账，不增加原数量；支持多项一起登记。 |
| 修改 / 删除 | 可单项修改基础信息，也可批量修改实物编号、条形码及日期。删除要再次确认；有引用、盘点、借还或处置历史时拒绝删除，保留完整业务历史。 |
| 新增套装 | 工具资料 → 工具套装 → 新增；选同一工具库内成员及组成数量。勾选套装后可整套借出、一次填写所有可还成员归还量。套装及成员不能同时重复选入一笔领用。 |
| 借出 / 归还 | 借出填人员、类型和归还期限；归还自动列出所选工具对应的全部未还行，可逐项填本次归还数量。 |
| 调拨 | 只在检修工具库与整备工具库之间，自动确定相反方向；点击“接收调拨”完成入库或取消。 |
| 送检 / 送修 | 填单位、数量及原因。完成后勾选对应工具，点底部“登记检修结果”；合格回库，不合格生成报废审核单。 |
| 遗失 / 报废 | 填数量和申请来源，借出遗失选择借用单；审核通过才处置数量，申请人与审核人不能相同。 |
| 详情与记录 | 单选工具后查看借还、检定、维修、审批历史；底部可维护标签状态、绑定工序和核验工具。 |
| 工具资料 | 用页内标签选择字典、分类、套装或设施，每张表底部均有新增、修改、删除。两个工具库是固定配置，不增加第三库。 |

## 现场勾选盘点

1. 点击底部“仓库盘点”，选择检修工具库或整备工具库，填写经办人。
2. 主区域变为工具盘点大表，显示每件工具的应有数量；左侧默认不勾选。
3. 现场找到工具后勾选“实际找到”。有编号工具实盘0或1；无编号工具勾选后填写实际件数，可记录多件、少件。
4. 未勾选工具在最终确认时按实盘0件处理。检查完所有行后，点击底部“确认清点完成”，查看总应有、实际数量，填写盘点结论和经办人再确认。
5. 系统在一笔事务中保存差异、更新库存并保留历史。盘点期间有借还或库存变化时会拒绝旧盘点，需要取消重建。
6. 点击“导出盘点状态”下载CSV，包含工具库、名称、编号、标签、应有、实际、差异、盘点状态、经办人及时间。未确认时导出明确标为盘点草稿；完成后标为清点完成。取消的盘点标为“已取消（未调整库存）”，实际数量标“未确认”，不伪造为实盘0件。
7. 点击“盘点记录”可重新打开旧盘点并导出，已完成记录不能再次修改。仅核对在库实物，不把借出或送检送修中的工具算作库内应有。

## 固定两库初始化

启动服务时自动执行一次两库配置。旧构架工具库等原检修用途库归到检修工具库，整备用途库归到整备工具库；保留实物及业务引用、数量。更改前备份保存在本机 `backups/before-fixed-tool-warehouses-*.json`，不提交Git。多库历史调拨如果无法安全归并会拒绝迁移，不自动改写成同库调拨。也可执行 `npm run db:tools-setup`；重复执行不改变已配置数据。

## 智能设施与持久化边界

“工具管理底部 → 工具资料 → 智能设施”维护工具柜 / 无人工具室资料；选择设施后可在底部联调模拟事件。模拟会执行库存业务，但不会把设备标记为在线。

所有业务通过PostgreSQL事务保存，并保留经办人、时间及审计；重复请求不重复入库，两个窗口同时办理有数据版本校验。套装归还和原库存登记已覆盖数据库回滚、幂等、重连及浏览器操作测试。工具柜读写器、定位、门禁控制和现场全天候运行仍须真实设备接入验收，不能用模拟替代。

## 设备协议

在本机 `.env` 或服务环境变量设置 `TOOL_DEVICE_TOKEN`，至少24个随机字符，不提交Git、不填入前端页面。未配置时接口返回503，错误密钥返回401。重启服务后生效。

接口：`POST /api/tools/device-events`。请求头 `Content-Type: application/json`、`X-Tool-Device-Token: <服务器配置的密钥>`。

```json
{
  "requestId": "cabinet-01-checkout-000001",
  "actor": "工具柜网关",
  "payload": {
    "deviceId": 1,
    "eventId": "checkout-000001",
    "eventType": "CHECKOUT",
    "tag": "现场标签值",
    "employeeId": 1,
    "quantity": 1,
    "dueAt": "2099-01-01T18:00:00",
    "scheduleTaskId": 1
  }
}
```

示例编号均须替换为当前库中的实际编号，日期为协议格式示例。真实请求时间由服务器记录，不能用请求中的日期伪造设备在线状态。

| eventType | 必填业务字段 | 处理 |
| --- | --- | --- |
| HEARTBEAT | deviceId、eventId | 更新真实设备最近通信时间。 |
| ENTRY | deviceId、eventId、employeeId | 记录门禁通行。 |
| CHECKOUT | deviceId、eventId、tag、employeeId、dueAt；quantity默认1 | 标签领用。可附scheduleTaskId进行工序比对。 |
| RETURN | deviceId、eventId、tag、employeeId、loanId；quantity默认1 | 标签归还到对应借用单。 |
| INVENTORY | deviceId、eventId、tags字符串数组 | 对比本库在库标签，记录差异，人工盘点确认后调账。 |

deviceId在所有事件中必填，设施须启用。每次业务请求的requestId须唯一；通信重试保留相同requestId和内容。同一设施的eventId也不能代表不同内容。认证成功但标签错误、工具不匹配或库存不足时，接口返回已接收并将 `eventStatus` 设为 `ERROR`，不扣减库存；网关必须检查该字段，不能仅凭HTTP200判断领用成功。

普通页面使用 `POST /api/tools/commands`，包含type、payload、actor、requestId和当前revision。只用于项目当前的受控演示访问环境。`GET /api/tools/alerts` 返回实时预警。所有写入和工具主表更新共用数据库事务。
