## 来源与展示范围

本地从 `0b0a245` 快进到远端 `e3be278`，新增业务提交为 `9b6120d`（月度计划完善），没有 Git 文本冲突。远端已经包含工具管理 `b4e4fe2`、工具界面调整 `f506a43` 和工具审批持久化 `0b0a245`。

展示导航保留月度计划、月度计划交验统计、检修排程、任务下发、计划审核与审批以及已有的工具管理等业务。年度、配件、临修及计划完善中心的开发代码和旧链接保留，从侧栏与全部功能目录收起，暂不用于正式展示。审批页面的主入口只展示月度车辆计划。

## 现在的操作顺序

1. 月度计划：在计划日历或计划列表点击“导入计划文件”。系统先生成预览，不写业务计划。逐行点击“编辑并重新校验”可修改机车编号、机型、修程、修次、入段日期、配属局段、公里数及备注；确认导入前重新校验字典、日期、重复计划和数据库冲突。备注按填写内容保留。
2. 检修排程：选择车辆和最晚完成时间，核对资源后生成模拟；调整时间或锁定任务后重新模拟，校验通过再点击“确认并提交审核”。
3. 计划审核与审批：查看该次提交的排程版本及工序、工位、班组明细。先审核通过，再审批发布。审批前不生成班组下发清单，发布后生成清单。
4. 重新排程：待审核或待审批发布时，在月度计划详情中“确认修改”，填写原因，撤回本次审批；已发布时先“申请调整”并填写原因。进入待修改状态后才能重新排程，形成新版本并重新提交两级审批。当前修改/调整申请在填写原因并确认后直接进入待修改，不包含额外的“申请本身再审批”环节。
5. 月度交验统计：在月度计划的“交验统计”页签，按月份、委修段、机型和关键词查看已发布车辆的交验安排与记录，查看每日趋势。没有实际交验记录时展示待交验，不能将安排数当作已交验完成数。
6. 工具管理：仍从“资源台账 → 工具管理”进入，使用原来的台账、借还与调拨、检定与维修、盘点与预警、智能设施五个视图。工具数量与状态仍参与检修排程资源校验。

## 本次整合修复

- 月度交验统计有独立入口，不再在侧栏误指向月度日历；图表天数按真实月份计算，覆盖28/29/30/31天。
- 导入预览的部分字段修改保留其他字段；不再用“重新校验通过”等提示覆盖业务备注，备注也可编辑。
- 打开网页不再自动写入演示计划、临修计划或改变车辆审批状态；演示数据只通过明确执行的初始化/种子脚本加入。
- 新审批绑定提交时的排程版本，重新编排后旧审批详情仍查看原版本；修复审批详情的责任班组关联。
- 月度审批与工具遗失报废审批共用现有 PostgreSQL `approval_record` 表，按业务类型区分，互不覆盖。
- 演示入口保留五个主功能页签，同时支持审批和交验统计的子页面跳转。
- 修复月度日历在大量当日车辆时右侧详情撑高的问题，列表在面板内滚动。

## 数据保存

- 月度审批流程、处理历史、调整原因、交验记录：随 `application_state` 的 JSONB 状态事务保存。
- 月度两级处理记录：物理表 `approval_record`，`business_type='MONTHLY_PLAN'`，`business_id` 为审批流程ID，`approval_level` 为1（审核）或2（审批发布）。每次重新提交使用独立流程ID；撤回/驳回保留处理结果。
- 工具审核：同表使用 `business_type='TOOL_DISPOSAL'`，保留申请、结果、意见和处理时间；工具流转详情仍保存在工具业务状态中。
- 月度审批界面目前未要求选择具体审核人员，处理记录中的 `approver_id` 因此可为空；不把“主管科长/主管副段长”步骤当作已实现账号权限认证。
- 合版未执行数据库重置或新增的月度独立演示初始化脚本，保留当前演示库数据。

## 验证

- `node tests/monthly_tools_integration.mjs`：同一独立 PostgreSQL 数据区覆盖提交、两级审批、修改申请、历史版本、工具领还与遗失审核、导入字段编辑、备注落库、交验记录及关闭重连。
- `node tests/monthly_tools_ui.mjs`：实际浏览器上传两车、编辑错误字段和备注、40任务模拟、提交、两级审批、申请调整、工具视图切换与建库、交验统计窄屏布局。
- `node tests/monthly_schedule_approval.mjs`：审批前不下发、审批后下发、申请修改后重新提报。
- 其他回归：工具业务与数据库、计划导入、排程模拟、保存恢复、导航及工作台布局。

以上测试使用独立数据区，结束后仅清理相应测试区。500轮PC1回归为已有压力测试的500个运行周期，不等同于500种完全不同的业务需求。
