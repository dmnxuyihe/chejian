# PC1 日历与展示演示交接

2026年10月27日，按本周计划中徐义合的分工完成。

## 已完成功能

| 周任务 | 当前实现 |
| --- | --- |
| 月度计划导入 | 支持 `.xlsx`、UTF-8/GB18030 CSV；预览行号、错误及重复项；确认后只保存有效行 |
| Excel演示模板 | 可直接下载标准XLSX模板，包含相邻入段日期两车；CSV保留为备用 |
| 计划维护及查询 | 新增、编辑和删除草稿写入PostgreSQL；重复计划拒绝；月度日历查询入口可查看三类视图 |
| 入出段月度日历 | 周一开头，可切月份、筛车辆；入段与正式排程的已排出段分别标记 |
| 单车每日任务 | 从日历或列表进入本车信息；显示跨日任务、当日完整清单和已完成任务比例 |
| 单车甘特图 | 读取同一排程结果，按任务展示起止时间、状态和锁定标记；可缩放日期范围、查看任务详情 |
| 车间每日任务日历 | 汇总多车每日任务，可筛选车辆；三条以上可展开当天全部任务 |
| 视图同步 | 单车、车间及月度标记均从共享状态计算，区分正式、未确认及模拟数据 |
| 演示记录保存 | 默认通过后端保存到PostgreSQL，刷新恢复；同一服务的其他页面自动获取共享更新 |
| 备份与复位 | 导出JSON备份、校验恢复、复位前确认并下载当前备份；本页可撤销 |

## 启动及操作

1. 在项目根目录运行 `node start.js --no-open`，打开终端显示的地址；默认端口为5173。
2. 沿用现有导航，进入“计划管理人员 → 月度检修计划 → 月度计划同步与编制”，直接地址 `/#/planning/plans`。
3. 点击“下载Excel模板”（或“CSV模板”）。模板包含相邻入段日期的两车，日期为10月27日、28日；直接填好保存并导入，无需手动转换格式。
4. 点击“导入月度计划”，选择文件。预览中可查看行号、入段、要求完成日期及校验结果，确认导入后查看月度日历。
5. 点击车辆进入“单车检修”；在“车间任务”中按日期查看多车任务，也可按车辆筛选。
6. 排程模块提供结果后，返回本页即可看到对应日历与甘特图；正式确认后才显示已排出段。
7. 页面上方“保存与恢复”可导出JSON备份、恢复其他备份或复位。复位会恢复项目原始的一车演示数据，不会生成两车排程；要演示两车须导入模板并由排程模块排程。
8. “月度计划日历查询”入口 `/#/planning/g2-p2` 可查看相同的月度、单车和车间任务视图；该查询入口不显示导入、新增、编辑或删除按钮。

手工新增默认使用当前日历选定日；未选日时使用本月今天或该月1日。保存后自动跳到车辆入段月，跨月编辑也会同步。新增和编辑按“车辆编号忽略大小写及首尾空白 + 入段日”校验重复，优先级0可正常保留。删除草稿先确认；已生成任务或正在模拟的车辆禁止直接删除。文件读取失败会清除旧预览，不能继续误导入上一个文件。

当前标签页的月份、选中日期和车辆保存在sessionStorage，刷新后回到原查看位置；其他标签页和其他电脑的筛选不受影响。业务计划和任务仍从PostgreSQL读取。

计划及排程在页面重绘后异步提交PostgreSQL，请以顶部“已保存到PostgreSQL”状态为准。备份包括计划、排程、人员资源分配、版本及模拟锁定；未经确认的导入预览、恢复确认和撤销缓存不保存。恢复或复位前会下载当前数据备份，本页可撤销；共享数据已有新版本时禁止直接撤销。恢复前校验格式与任务关联，失败时不替换当前数据。详见[PostgreSQL部署与迁移](PostgreSQL接入与演示部署.md)。

导入字段：机车号、入段日期为必填；最晚完成日期、优先级、累计走行公里、备注为可选。没有截止日期时，预览会明确显示默认值“入段后14天18:00”，供导入前核对；它是要求完成日期，不代表排程结果。Excel读取第一张工作表，日期支持文本及Excel日期数值，最多1000行、5MB。

重复规则为“车辆编号与入段日相同”，同时检查已有计划及本次文件。错误行和重复行均跳过，预览时不写入任何车辆。取消导入不改变已有计划。

## 排程模块接入约定

现有排程结果继续读取 `state.schedules`、`state.vehicleRepairs` 和 `state.scheduleVersions`，不另建一份日历任务数据。未排程的零时长占位不显示；未确认结果标记为“待确认”。已排出段取当前发布版本车辆任务的最晚结束时间，不取要求交车日期。

魏思冰的模拟模块可向共享状态提供：

```js
state.pc1SchedulePreview = {
  vehicleRepairIds: [2, 3],
  schedules: [
    {
      id: 21,
      vehicleRepairId: 2,
      taskId: 1001,
      workstationId: 1,
      plannedStartAt: '2026-10-27T08:00:00',
      plannedEndAt: '2026-10-27T09:00:00',
      status: 'NOT_STARTED',
      isLocked: false,
    },
  ],
}
ctx.rerender()
```

`schedules`须包含参与车辆完整的当前模拟结果，时间采用本地无时区字符串。日历和甘特图会使用模拟任务替换参与车辆的显示，其他车辆保持原结果；正式出段标记仍按正式数据计算。重新模拟、拖动及锁定后更新此对象并重绘即可同步视图。取消模拟时删除该对象。确认时由排程模块保存正式任务及版本，清除预览对象后重绘。本次只实现读取和展示该约定，没有实现模拟算法、拖动调整或确认发布动作。

王俊杰的资源清单继续使用当前车辆ID `state.selectedVehicleRepairId`，可在单车信息页接入清单。当前页未新增工具、物料需求或库存逻辑。

## 当前限制

当前默认使用PostgreSQL，同一服务地址下的电脑共享计划排程；旧版localStorage记录可在“保存与恢复”中迁移。多车模拟、拖动锁定确认及人员工具物料清单仍需按分工由相应成员接入。本次浏览器测试通过现有排程API生成两车结果，并单独验证模拟显示约定，不代表其他成员的模拟交互已经完成。

离线Excel解压使用随项目附带的JSZip 3.10.1，许可位于 `vendor/JSZip-LICENSE.markdown`。
