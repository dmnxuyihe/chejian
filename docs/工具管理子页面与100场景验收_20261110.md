# 工具管理子页面与用户操作验收（2026-11-10）

## 页面结构

左侧“工具管理”下固定显示四个子项：

1. **工具台账**：工具和实物统一查询；新增、修改、删除在台账内完成。选中行后，借出、归还、调拨、送检、送修、遗失申请、报废申请等操作出现在表格下方，且清楚展示已选工具及当前状态。
2. **盘点**：创建或重新打开盘点单；逐项记录实盘、确认差异、导出和回看历史都在盘点页完成。
3. **业务记录与预警**：查询借还、调拨、送检、送修、遗失报废审核、库存/检定/超期预警、设备事件和审计记录；所选记录的办理动作在记录列表下方。
4. **工具资料**：工具字典、工具分类、工具套装和智能设施在同页分类维护；各资料表提供新增、修改、删除。工具库固定为检修工具库、整备工具库。

台账表格提示压缩为操作指引；盘点列表未选择记录时禁用“打开所选盘点”，选中后显示单号并启用。该目录是工具管理的页面组织，不改变业务对象、审批状态或数据库结构，也不意味着已连接实物 RFID/智能柜/门禁。

## 用户视角 100 组

运行 `npm run test:tools:user100`。测试在隔离 PostgreSQL schema 和 Microsoft Edge 中完成，脚本结束后删除测试 schema，不写正式演示数据库。场景组合为：

- 25个不同工具编号搜索、勾选及底部借出/调拨入口检查；
- 25张不同历史盘点单打开、状态读取和导出入口检查，并检查未选中/已选中时按钮启用状态；
- 25组业务记录类型、办理范围和空结果查询组合；
- 25组工具资料分类、字典、套装和设施页签及 CRUD 入口检查。

这是一组自动化用户流程模拟，不是100名真实操作人员访谈。页面走查发现台账有15列，部分桌面宽度仍需横向查看；为避免滚动后认错行，现冻结勾选框、工具名称和编号列，其他字段仍可横向查阅。固定底部操作区在390px宽度下占视口约25%，页面没有横向溢出。现场观察时仍应留意操作区遮挡及其余列的查找成本。

`npm run test:tools`现包含工具域、PostgreSQL、1000组领域组合、既有交互和新增页面/100场景回归。
