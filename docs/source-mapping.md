# Source Mapping

本工程的功能职责以用户确认的需求表为准，演示范围、工艺流程、数据结构和视觉参考分别追溯到对应来源。

## Functional Requirements and Demo Scope

功能依据：`高级修检修车间信息化需求.xlsx`（仓库副本位于本目录）。已与用户于2026年10月28日提供的桌面文件逐单元格核对，内容相同。

演示场景依据：用户提供的《2026-10演示.docx》；同时保留用户对两车选择、资源预检、模拟、拖动、锁定、重新模拟及确认的补充要求。

细分任务职责、演示对应行号和当前缺项见[演示计划与需求表逐项对应](演示计划_需求表逐项对应.md)。表中的ERP、MES等标签不代表开发成员姓名；页面已建立或测试通过，也不代表对应整条需求完整实现。

## Database Structure

来源：`智能排程+配件(1).xlsx`

用途：

- 第一版数据库结构理解
- 排程核心表关系
- 配件新增结构：类型、实例、任务需求、排程分配、流转

原则：配件只做排程必需补充，不替代原有备件。

## Process Definition

来源：`构架_轮驱检修流程(1).xlsx`

用途：

- 构架与轮驱任务名称
- 流程先后顺序
- 标准工时参考
- 任务步骤提示

原则：工艺配置提供任务和依赖约束；按需求表第18行及用户补充要求，排程界面应支持约束内的任务时间及允许的顺序调整。图形化调整不能绕过工艺依赖，也不能因冻结了工艺节点而取消本次演示要求的调整能力。

## UI Reference

参考：用户提供的 production-dashboard / inventory 页面风格。

实现方式：保留类似的工业后台布局、浅色卡片、侧边导航、KPI、表格与排程信息密度，但工程本身使用无第三方依赖的 ES Modules + CSS，避免安装依赖后才能启动。
